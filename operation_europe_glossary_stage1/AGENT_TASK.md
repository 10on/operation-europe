# Задание агентам: Этап 1 — глоссарий и описание интерфейса Operation Europe

## Цель
Собрать машиночитаемую базу знаний для Sega Mega Drive / Genesis Operation Europe: Path to Victory 1939–45. Пока **не** писать игровой агент, не разрабатывать протокол команд и не выполнять реверс-инжиниринг бинарников. Только разобрать тексты и доступные изображения мануалов, описать терминологию и интерфейс.

## Источники
Использовать `SOURCES.md`. В первую очередь Genesis FAQ и официальный Genesis manual. SNES и DOS — лишь для сравнения, обязательно указывать платформу. Не принимать сведения о другой платформе за подтверждение Genesis.

## Рабочий процесс
1. Скачать/открыть доступные источники, записать provenance (URL, заголовок, автор, версия, дата доступа, раздел/страница). Не складывать защищённые полные тексты в публичный репозиторий.
2. Извлечь полный перечень игровых терминов: сущности, атрибуты, статусы, ресурсы, приказы, роли командиров, экраны, меню, сообщения, кнопки, игровые фазы, боевые механики.
3. Составить `glossary.yaml`: canonical_id (стабильный английский snake_case), display_en, display_ru, aliases_en, aliases_ru, category, definition_ru, scope, source_refs, confidence, verification_status. Сохранять точные игровые сокращения (`Tact`, `SpFc`, `Sply` и т. п.) отдельно от полных названий.
4. Составить `ui_screens.yaml`: screen_id, назначение, визуальные ориентиры, области интерфейса, меню/пункты, доступные кнопки, входы/выходы, модальные вопросы, ссылки на источники, степень уверенности. Отдельно стратегическая карта, информация о юнитах, меню приказов, тактический бой, начальные экраны и системное меню.
5. Составить `ui_transitions.yaml`: from_screen, trigger (кнопка/выбор пункта), to_screen, prerequisites, expected_observation, source_refs, status. Не выдумывать отсутствующие переходы.
6. Составить `mechanics_notes.md` — краткие фактические заметки, необходимые для понимания интерфейса, не стратегическое прохождение.
7. Составить `unverified_questions.md`: расхождения источников, неизвестные детали, что нужно проверить в реальной Genesis игре и позже в DOS.
8. Составить `source_index.yaml`: URL/платформа/автор/версия/разделы/страницы/лицензионные ограничения.
9. Провести вторую независимую проверку: все записи с `verified_from_source` должны иметь проверяемую ссылку на конкретный раздел или страницу; `verified_in_game` — только после фактической проверки в игре.

## Требования к качеству
- Различать *название меню*, *приказ подразделению*, *кнопку контроллера* и *игровое действие*.
- Не смешивать `STRATEGIC` и `BATTLE` для одинаковых слов (например, Move/Attack).
- Не приписывать игре значения и координаты, которых нет в источнике.
- Русские названия — собственный согласованный перевод, исходные английские названия обязательны.
- Для неоднозначных терминов перечислять варианты и задавать статус `needs_game_verification`.
- В начале каждого выходного файла указывать версию схемы и дату обработки.
- Проверить, что YAML парсится, ID уникальны, ссылки на источники существуют.

## Definition of done
Полный список терминов и экранов, описанных в доступных источниках, с привязкой к источникам; таблица переходов; список непроверенного. Никакого придуманного API управления игрой на этом этапе.
