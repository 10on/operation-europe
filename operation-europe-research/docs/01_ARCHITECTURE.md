# 01. Архитектура двух машин

## Роли узлов

```text
                    ┌────────────────────────┐
                    │ CLOUD REVIEWER (редко)  │
                    │ обзор отчётов, задания  │
                    └───────────┬────────────┘
                                │ compact evidence report
                    ┌───────────▼────────────┐
                    │ MAC M1 Max 64GB        │
                    │ Qwen3-VL / OCR /       │
                    │ categorization         │
                    └───────────┬────────────┘
                                │ images/results through SSH/SMB
                    ┌───────────▼────────────┐
                    │ WINDOWS i7-4790K       │
                    │ Ghidra + DOSBox        │
                    │ Automation + DOSBox-X  │
                    │ source files & tests    │
                    └────────────────────────┘
```

Изображения и дампы хранятся на Windows; Mac получает **вырезки экрана или JPEG/PNG по требованию**, не поток VNC 60 FPS. VNC — только для ручного администрирования. Скриншоты без VNC даёт API эмулятора; это дешевле и точнее, позволяет брать native framebuffer (без масштабирования/антиалиасинга). Не отправляй каждый кадр в Vision: запускай только после смены состояния.

## Сеть: минимально необходимое

Рекомендуемый вариант: OpenSSH Server на Windows, доступ с Mac по локальной сети с ключами, SFTP/SCP для артефактов; отдельный разрешённый каталог данных. Альтернатива — SMB-общая папка, но права записи давать только рабочей области. Если нужен API с Mac, пользоваться `ssh -L 8386:127.0.0.1:8386 windows-user@windows-host` (Mac как клиент); DOSBox Automation продолжает слушать **127.0.0.1** на Windows. Важно: порт Mac не должен быть занят собственным приложением; можно выбрать `-L 18386:127.0.0.1:8386`.

Нельзя публиковать DOSBox API в интернете: чтение/запись памяти и клавиатура = полный контроль над эмулятором. Не хранить bearer-токен в Git, выводах или логах.

## Оркестрация: не тащить сложную инфраструктуру раньше времени

Версия 0: один координатор на Mac, один исполнитель на Windows, обмен `task.json` / `report.json` в рабочей директории или Git-коммитами. Использовать **одного** исполнителя на конкретный эмулятор/снимок игры: два агента, одновременно нажимающие клавиши, испортят опыт.

Версия 1 (при десятках независимых задач): очередь `pending/running/done/failed`, атомарное присваивание локальным брокером или SQLite (только если БД на одном хосте, **не** SQLite по нестабильному SMB). Очередь — **только транспорт задач**; не путать с Qwen как моделью. Желательно отделить задачи `binary-analysis`, `emulator`, `vision`, `review`.

## Хранение

- `private/game-dos` — неисполняемый мастер-каталог неизменённых файлов, без контроля версий.
- `private/game-dos-working` — копия для DOSBox, сохранений и патчей.
- `artifacts/inventory.json`, `artifacts/experiments/<id>` — записи опытов.
- `knowledge/` — описания таблиц, функции Ghidra с адресами, фактологические записи; Git для истории.
- `reports/` или `artifacts/reports/` — маленькие JSON + Markdown summary для облачного агента.

## Основной цикл со статусами

`QUEUED -> CLAIMED -> RUNNING -> VERIFYING -> COMPLETED` либо `BLOCKED/FAILED`. Любой loop ограничен максимумом попыток и ожидаемым состоянием GUI. При несоответствии состояние **не исправлять угадаными кликами**: снять PNG, остановиться, открыть issue.

## Экономия токенов

1. Для скриншотов сначала **hash** кадра, затем поиск ROI, шаблоны/OpenCV, Tesseract и только в трудном случае Qwen-VL.
2. Для бинарника — `file index + addresses + candidates`, не отправлять весь disassembly облаку.
3. Группировать одинаковые OCR ошибки и обучать шаблон один раз.
4. Облачный review пакет ограничить обзором на 1–3 страницы; глубокие материалы доступны локально по ссылкам/хешам.

## Рекомендуемые альтернативы

- DOSBox Automation: управление/метрики/снимки/запись ввода.
- DOSBox-X Debugger: запуск до entry point и breakpoints (отдельный эмулятор, состояние не обязательно совместимо).
- Ghidra Headless: тяжёлые batch-анализы запускаются на Windows и выполняются CPU; GPU A2000 для этого не нужна.
- Vision: запуск на Mac через MLX; VNC нужен редко.
