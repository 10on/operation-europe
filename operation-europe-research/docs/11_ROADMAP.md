# 11. План выполнения с контрольными точками

Это порядок задач и проверок, **не календарная оценка**. Нельзя обещать сроки без наличия игры и первых результатов.

## Фаза A — достоверный фундамент

- A1: приняты/зафиксированы DOS-файлы и их SHA-256.
- A2: установлен loader executable, overlays/упаковка (если есть), видеорежим и способ запуска.
- A3: записан хотя бы один штатный save и одна пара screenshot + action.
- A4: Ghidra project и baseline inventory функций.

**Выход A:** reproducible environment. Если DOS-версия не запускается, останавливаться на диагностику среды, не переходить к анализу AI.

## Фаза B — структуры данных

- B1: экран одной сущности, поля и контрольные цифры.
- B2: RAM scan двух состояний, исключение экранного буфера.
- B3: file/Ghidra/runtime mapping для одной структуры.
- B4: второй тип структуры (equipment/terrain/scenario), cross-references.

**Выход B:** хотя бы одна **confirmed** структура с воспроизводимым способом извлечения.

## Фаза C — движок

- C1: запреты приказов / admissible actions.
- C2: движение, стоимость клетки и ограничения.
- C3: обработка конца хода и эффект снабжения.
- C4: боевые формулы, RNG, rounding, state updates.
- C5: AI order selection, условия победы.

**Выход C:** набор golden fixtures с одинаковыми результатами оригинала и нашей реализации для deterministic ситуаций.

## Фаза D — современная игра

- D1: engine как headless TypeScript-пакет, CLI для пошагового тестирования.
- D2: карта/подразделения + ввод мышью; цвета и элементы интерфейса собственные.
- D3: сохранения в versioned JSON + миграции схемы.
- D4: справка, доступные действия, история хода, undo там, где позволяет механика.
- D5: русская локализация, планшет/десктоп, опционально сравнение с Genesis.

## Условия пересмотра стратегии

- Исполняемый файл невозможно статически разобрать из-за упаковки/overlay: переключиться на runtime dump/unpacker identification; не применять случайные бинарные патчеры.
- DOS сильно отличается от Sega: сохранять отдельные спецификации поведения; выбрать целевой reference на основе пользовательского опыта.
- OCR постоянно ошибается: переключить numeric extraction на RAM + шаблоны, оставить Vision классифицировать GUI.
- Невозможно стабилизировать RNG: тестировать статистически и документировать ограничения exact-match.
