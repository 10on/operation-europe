# Общие правила AI-агентов

Проект изучает DOS-игру **Operation Europe: Path to Victory 1939–45**, не System Shock и не игру под рабочим названием Europa. Приоритет: статический анализ, затем динамическая проверка. Источник истины — фактические локальные файлы и воспроизводимые измерения.

1. Не утверждай, что видел бинарники, карту памяти, таблицу или код, если нет конкретного артефакта, SHA-256, смещения и способа проверки.
2. Сначала прочитай `README.md`, `docs/00_SCOPE.md`, а также инструкцию своей роли в `agents/`.
3. На каждую задачу создавай `report.json`: ID, цель, методы, окружение, вывод, confidence, доказательства, открытые вопросы, следующий опыт. Схема: `schemas/report.schema.json`.
4. Ложноположительные результаты, нулевые результаты и тупики тоже фиксировать. Отчёт должен содержать проверяемое отрицательное наблюдение, если гипотеза не подтвердилась.
5. Не загружай бинарники, большие дампы памяти или большие пакеты скриншотов в облако. Для облака — краткое резюме, ссылки на локальные пути, хеши, **небольшие** важные вырезки/ассемблер и список решений.
6. Не распаковывай сомнительные EXE запуском в обычной системе: DOS-программы — через эмулятор, любые Windows-утилиты из неизвестных источников — через проверку/песочницу.
7. Никогда не изменяй оригиналы в `private/`; работай с копиями и помечай патчи.
8. Не смешивай смещения **файла**, виртуальные адреса **Ghidra**, `segment:offset` и физический линейный адрес. Формула real-mode адреса `segment*16 + offset` — только при соответствующем режиме и контексте; учитывай relocations/overlays/A20.
9. OCR и Vision не являются доказательствами сами по себе. Для чисел сохраняй crop PNG, распознанное значение, уверенность, метод и вторую проверку/сравнение с памятью.
10. В ходе исследования не публикуй оригинальные ресурсы, бинарники, ROM и большие оригинальные текстовые блоки.
11. Все сети для доступа к эмулятору — только loopback или защищённый туннель. Не открывай API с правом записи памяти в публичную сеть.
12. Критерий `done`: выполнен артефакт, тест воспроизведения, отчёт и короткий список оставшихся неопределённостей. Не заменять измерения уверенностью LLM.

## Степени достоверности

- `confirmed`: код + воспроизводимый тест или не менее двух независимых проверок.
- `observed`: воспроизводимый эксперимент с контрольным исходным состоянием.
- `inferred`: гипотеза по косвенным признакам (адрес, таблица, GUI).
- `unknown`: нет надёжных доказательств.

Не называй вероятности числовыми процентами без основания. `confidence` — один из вышеперечисленных статусов.

## Рабочий цикл

`claim task -> inspect inputs -> record environment -> execute bounded experiment -> validate -> report -> propose next step`.

Если задача требует отсутствующего диска, указать это как блокер и выполнить только доступную подготовку: скрипты, шаблоны, тесты на синтетических данных.
