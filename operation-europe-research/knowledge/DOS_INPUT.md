# Управление DOS-игрой через инструменты (мышь, клавиатура) — проверено 2026-10-26
Статус: observed (проверено на DOSBox Automation 0.85.1, игра запускалась из `private/game-dos-working`).

## Быстрый вход (без роликов): `oe-boot [menu|scenarios]`
Запускает DOSBox с `fmdrv` + `main` (минуя koei/open.exe — интро Koei и ~25 с загрузки), сам выбирает мышь, ждёт меню по пикселям и (`scenarios`) открывает список сценариев. Итого **~6 с** вместо ~27 с через koei. Мышь при этом работает (проверено). Скрипт: `scripts/boot_game.py`; `--input keyboard` выбирает режим клавиатуры.
Причина: `fmdrv.com` (резидентный FM-драйвер) нужен игре для мыши/звука; `main` без него даёт игру без курсора. Интро (`open.exe`) Esc/клавишами быстро не пропускается (~24 с), поэтому оно просто не запускается. Скорость CPU на время входа 200000 циклов/мс, затем 50000.

## Как запускать игру
- **Штатно: `koei`** (`oe-dosbox -Run koei`). Лаунчер `koei.exe` по цепочке грузит `fmdrv.com` (OPL-звук), `open.exe` (интро Koei, пропускается Esc), `main.exe`, `end.exe`; в нём есть INT 33h (инициализация мыши). Строки в koei.exe: FMDRV.COM, OPEN.EXE, MAIN.EXE, END.EXE.
- Запуск `main.exe` напрямую даёт игру без курсора мыши — **так не делать**.
- Загрузка `main` занимает ~25–45 с после интро. Экран на старте: «Select Keyboard (with any key) OR Mouse (with click)» — клик = режим мыши, любая клавиша = режим клавиатуры. Режим выбирается на запуск игры.

## Драйвер мыши (INT 33h) — проверено отдельной тест-программой `private/dos-tools/mtest.com` и `mtest12.com`
- Драйвер есть: INT 33h vector C90D:0010 (встроенный драйвер DOSBox), reset: AX=FFFF, BX=FFFF (2 кнопки).
- API: только **относительное** движение (`x_rel`, `y_rel`), абсолютного позиционирования нет; левая/правая/средняя кнопки; колесо.
- Клики видны драйвером: левая = 1, правая = 2 (проверено `AX=3`).
- Масштаб (стандартное INT 33h, 8:16 мик/пиксель): **X 1:1, Y вдвое медленнее** (двигать по Y на 2×). Проверено: +100 X -> +100; +100 Y -> +50.
- Позиционирование на «абсолютные» координаты: `mouse-home` (-4000,-4000: упирается в 0,0), затем сдвиг (x, 2*y). Команда `oe-ctl mouse-to X Y` делает это (в режиме 640x480).
- Курсор игры виден на скриншотах API (в режиме 12h рисуется в VRAM); наведение подсвечивает кнопки.

## Подтверждено на игре (режим 640x480, VGA 12h)
- `mouse-to 95 235` -> курсор на «Load Game» (подсветка); `mouse-to 95 211` + `click left` -> «New Game» -> список из 6 сценариев; `mouse-to 160 267` -> наведение на «D-Day at Normandy».
- В режиме клавиатуры (любая клавиша на стартовом экране): Enter на меню = «New Game» -> список сценариев.

## Команды (после `. .\scripts\env.ps1`)
`oe-ctl run "koei"` ввод+Enter | `oe-ctl key KBD_enter` | `oe-ctl keys KBD_esc KBD_enter` | `oe-ctl mouse-to X Y` | `oe-ctl mouse-move dx dy` | `oe-ctl click [left|right|middle]` |
`oe-ctl shot out.png` | `oe-ctl text` (текст-режим) | `oe-ctl cpu` | `oe-ctl mem SEG OFF LEN` | `oe-ctl state`.
Имена клавиш — `KBD_*` (enter, esc, space, up/down/left/right, f1..., a..z). Файлы в DOS — 8.3 (`mtest`, а не `mousetest`).

## Прочие возможности API (из openapi.json): cpu/state, cpu/register (PUT), cpu/cycles, memory read/write/search/freeze/allocate, io/port, dos/internals (MCB), video/frame|text, input/record (запись ввода), script (Lua), capture/video (ZMBV), drive/swap.
**Нет:** точек останова/отладчика в Automation (`debugger: false`). Для отладки: DOSBox-X (`oe-dosboxx -Run koei`, отладчик Alt+Pause) — у него нет HTTP API; режим игры в нём не проверялся глубже запуска (окно «OPEN – 3000 cycles/ms»).

## Неизвестное / ограничения
- Размеры и позиции кнопок в других экранах (карта, меню команд) не сняты; масштаб Y может меняться, если игра переключит соотношение мик/пикс (AX=0Fh) — перекалибровывать по подсветке/курсору.
- DOSBox-X: управление только вручную/через окно; конфиг `private/dosboxx.conf` генерируется из `config/dosboxx.conf.template`.

## `oe-boot newgame` — от меню до стратегической карты (France, Allies, Very Easy) — реализовано 2026-10-26
`oe-boot newgame` (по умолчанию **клавиатура**, ~65 с; `-Show` — показать окно; без флага окно DOSBox открывается свёрнутым и не забирает фокус).
Проходит: сценарий France -> предыстория -> One Player -> Allies -> Field Map -> «Don't View Battles» -> Very Easy -> настройки OK -> способности -> 7 офицеров -> 3 подтверждения -> реплики -> карта. Опции `boot_game.py`: `--side allies|axis`, `--difficulty veryeasy..veryhard`, `--battles view|dont|choose`, `--input keyboard|mouse`.
Что выяснено при реализации:
- **Клавиатурный режим** игры (любая клавиша на старте): Enter = левый клик, ESC/0 = правый; Down/Up двигают выделение. Детерминированно, не требует калибровки курсора — надёжнее мыши.
- Экран офицеров: Enter выбирает подсвеченную строку; **уже выбранного офицера выбрать нельзя** (нет реакции) -> нужно Down (список сам прокручивается). Успех — портрет в рамке (проверка по яркости).
- Текст предыстории печатается побуквенно: клик/Enter до конца печати игра игнорирует -> ждать, пока экран перестанет меняться. Мигающий значок «ждёт клика» — шум; для остального ожидание стабильности ограничено 2.5 с.
- Режим мыши (`--input mouse`) для `newgame` частично работает: курсор не всегда попадает в точку (расхождение до 25 px по Y), нужна обратная связь по положению курсора на кадре; по записи игрока шум движений мыши — от окна, которое мешало.
- Колесо мыши в игре ни на что не влияет (подтвердил игрок).
- Известные ограничения: офицеры выбираются «верхние» по списку (Bauxdey как Army Cmndr и т.д.), способности не перебрасываются; одиночный сценарий France; Load Game не проходился.
