# Локальные модели в исследовании

Приоритет пользователя от 2026-10-29: продолжать реверс, одновременно переносить подходящие небольшие задачи на локальные скрипты и дешёвые модели. Измерять полезность на задачах проекта, а не выбирать модель по обещаниям общего бенчмарка.

## Первый рабочий опыт: LOCAL-001

Из каталога `operation-europe-research`:

```powershell
python scripts/local_model_probe.py prepare
python scripts/local_model_probe.py grade artifacts/experiments/LOCAL-001/answer.json
```

`prepare` ничего не исполняет из игры: читает мастер-копию, проверяет SHA-256 main.exe, сверяет 60 инструкций существующего Ghidra-экспорта и две DOS-обёртки, проверяет арифметику seek и делимость размера scedata. Затем создаёт шесть коротких вопросов, эталон и запрос для Model Router. `expected.json` модели не передавать. `grade` требует ровно заданные ключи и варианты ответов; объяснения и Markdown вместо JSON отвергаются. Это маленькая диагностическая проба, не оценка общей точности модели.

Роутер на момент проверки сообщил здоровые бэкенды `gemma4-e4b`, `mac`, `a2000`. Название backend не доказывает имя/квантизацию реально загруженной модели: их и выбранный маршрут фиксировать из результата каждого вызова. Запрос использует `private=true`, `temperature=0`; tier `standard` требует разрешения владельца согласно описанию инструмента. Сам скрипт не делает сетевых запросов. API-ключи не нужны для подготовки/проверки.

## Что отдавать инструментам

| Задача | Первый исполнитель | Проверка результата |
|---|---|---|
| SHA, размеры, смещения, совпадение байтов, арифметика 16 бит | Python | Полный перебор ограниченного диапазона, эталонные байты |
| Классификация коротких функций и предложение имени | Локальная текстовая модель | Список допустимых классов; инструкции и вызовы; выборка вручную |
| Поиск пропущенного доказательства в коротком отчёте | Локальная модель / Jev Choice | Контрольные случаи с неизвестными DS, runtime AX, размером чтения |
| Выбор следующего эксперимента из готового списка | Локальная модель / Jev | Выполнимость, стоимость, возможность различить гипотезы |
| OCR отдельного поля UI | Локальная vision-модель | Crop и повторная проверка памятью/вторым наблюдением |
| Неизвестная формула боя или цепочка сегментных преобразований | Исследователь + дизассемблер | Код и независимый эксперимент |

Прямые DOS-сигнатуры из первых двух вопросов проще классифицировать скриптом: они служат контролем, не обоснованием расходов на LLM. Для модели полезнее неоднозначные функции и отсев необоснованных выводов. Пока не делаем общий агентский фреймворк: одна команда подготовки, один ограниченный вызов, один строгий оценщик.

Для каждого модельного опыта сохранять request, неизменённый response, backend/model (если доступны), время полного запроса, доступную usage-статистику, schema failures и ошибки по каждому случаю. Отдельно считать ошибки, при которых модель выдала неизвестное за установленное. Повторные вызовы и ручное исправление ответа включать в стоимость. Самооценку модели не переводить в проектный `confidence`.

Следующий набор должен включать новые, не использованные при настройке примеры; синтетические изменения AH, перезапись регистров, отсутствие DS, неуспешный read. Сравнить одинаковые входы на доступных Gemma/Qwen/gpt-oss, если соответствующие модели реально установлены. До измерений не обещать ускорение и не скачивать большие веса.

## Jev: кандидат для коротких решений

Проверено 2026-10-29 по [анонсу TypeSafe](https://typesafe.ai/blog/introducing-system-one-models-and-jev) и [документации](https://docs.typesafe.ai/introduction). Документация описывает Choice, Score и Noul; модель принимает состояние и типизированные вопросы, а не генерирует произвольные тексты/скрипты. Поэтому здесь наиболее естественны выбор категории функции, флага достаточности доказательств и следующего опыта из заданных вариантов.

В анонсе указаны $0.042 за миллион входных токенов и бесплатный выход; это заявление поставщика, не замер нашего счёта и не проверка текущего тарифа аккаунта. Например, 1000 запросов по 2000 входных токенов по этой ставке дают $0.084 только за токены. Доступ early access, реальный биллинг, лимиты и качество x86 пока не проверены. Наших запросов в Jev не было.

Гарантия структуры ответа не гарантирует истинность выбранного варианта. Опубликованные workflow evals используют ответы других моделей как ориентир; для реверса нужен наш эталон по коду/байтам. В облако отправлять только короткие собственные описания и минимальные фрагменты, без бинарников и дампов. Подключать Jev после воспроизводимого локального baseline, на том же наборе вопросов.


## LOCAL-001: выполненные вызовы 2026-10-29
Пользователь разрешил standard и рекомендовал oss. Выполнено 5 запросов: первый вернул work service is unavailable (62.1 с); decision — empty_answer после 1024 токенов на mac и gemma4-e4b (40.3 с). Три одиночных text-запроса обслужила gemma4:e4b: DOS AH=3Fh ошибочно unknown (12.2 с), отсутствие доказательства полного чтения — правильно No (8.7 с), runtime CF=0/AX=12 — правильно 12 (8.1 с). Это адаптивная проба, не общая точность 2/3. Модель на Mac не идентифицирована; интерфейс не позволяет выбрать gpt-oss по имени. Сырые ответы и запросы: artifacts/experiments/LOCAL-001/run-01..05.json и request*.json; сводка model-results.json. Jev пока не вызывался.
