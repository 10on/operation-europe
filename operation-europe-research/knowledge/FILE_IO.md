По каждому указанному вызову Ghidra декодирует `LEA BX,[offset]`, затем дальний `CALLF`; flow target — `1977:000E` (соответствие file offset `0xF77E` проверено короткими байтами). Отдельная последовательность `MSG` по file offset `0x594AB` существует, но найденный здесь шаблон `LEA BX,[0x2F48]` указывает на первую строку. Непосредственная строка `EMSG` в `main.exe` поиском ASCII и в Ghidra не найдена.

Код `1977:000E` помещает `0x0002` и `BX` в стек и вызывает `1000:001E`. Код `1000:001E` (file offset `0x601E`) переносит аргумент имени в `DX`, режим в `AX`, устанавливает `AH=0x3D`, вызывает `INT 0x21` и возвращает `0xFFFF` при carry. Это **подтверждает вызов DOS-функции открытия файла** из общего wrapper. Связь каждого `LEA` с указанной строкой пока `inferred`: смещения совпали с положениями строк внутри `CODE_90`, но значение `DS` в пяти точках не измерено.

Автоматический поиск Ghidra дал **0 references** на сами строки и до, и после ограниченного 120-секундного автоанализа. Это проверяемый отрицательный результат, а не отсутствие обращений: ручной поиск `LEA` нашёл пять кандидатов. Полного графа xrefs и размеров последующих `read`/`seek` здесь нет. Гипотеза о 12 записях по 800 байт в начале `scedata` остаётся `inferred`.
