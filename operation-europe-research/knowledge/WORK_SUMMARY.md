# Как идёт работа над реверсом Operation Europe (сводка на 2026-10-29)

Источники: `knowledge/STATE.md`, `AGENTS.md` (корень и `operation-europe-research/`), `README.md`. Это сводка, а не новый факт: статусы взяты из отчётов, которые упомянуты в STATE.md.

## 1. Цель

- Понять движок стратегии Koei из DOS-версии и в перспективе написать современный порт (TypeScript/веб).
- Sega Genesis-ROM — только референс поведения. Считать его тем же движком нельзя.

## 2. Метод

Рабочий цикл из `AGENTS.md`:

`claim task → inspect inputs → record environment → execute bounded experiment → validate → report → propose next step`

Правила, которые соблюдаются постоянно:

- **Доказательства.** Каждое утверждение сопровождается файлом, SHA-256, смещением и способом проверки. Без этого оно не считается фактом.
- **Уровни достоверности:** `confirmed` (код плюс воспроизводимый тест или две независимые проверки) > `observed` (воспроизводимый эксперимент с контролем) > `inferred` (косвенные признаки) > `unknown`.
- **Не смешивать адреса.** Смещение в файле, адрес Ghidra, `segment:offset` и линейный адрес — разные вещи.
- **Приоритет источников:** дизассемблер > дамп памяти > эксперимент > гайды > догадка модели.
- **Отчёт на каждую задачу.** `report.json` по `schemas/report.schema.json`: ID, цель, методы, окружение, вывод, confidence, доказательства, открытые вопросы, следующий опыт. Отрицательные и ложные результаты тоже записываются.
- **Оригиналы.** Файлы в корне `Operation_Europe_Path_To_Victory_1939_To_45/` и `*.gen` только для чтения и не коммитятся. Работа идёт с копиями в `operation-europe-research/private/` (в `.gitignore`).
- **Облако.** Передаются краткие резюме, хеши и короткие вырезки. Бинарники, большие дампы и скриншоты туда не отправляются.

## 4. Что уже установлено

**Файлы DOS-версии.** Инвентаризация 2026-10-26: 43 файла (`artifacts/inventory.json`).

- `main.exe` — MZ, x86 16-бит real mode; entry и размеры образа совпадают с заголовком. Основной движок.
- `scedata`: 66601 байт. Первые 9600 байт — 12 текстовых блоков по 800 байт с нулевым дополнением. Совпадает с кандидатом структуры `9600 + 7 × 8143` (`inferred`).
- `msg`/`msg.16p` и `emsg`/`emsg.16p` — каждая пара побайтно одинакова.
- `mapinf.dat`, `mappno.dat`, `hexdisp.dat` — по 9600 байт. Назначение не установлено.
- `hexmap.dat` — байты типов местности, малые значения (05/09/0a). Геометрия не выведена.

**Работа с файлами в коде** (статика, `FILE_IO.md`, `TASK-006`–`TASK-009`):

- Пять точек в `main.exe` передают адреса рядом со строками `SCEDATA`, `HEXMAP.DAT`, `MSG` в общий wrapper `INT 21h/AH=3Dh` (open).
- Wrapper чтения — `INT 21h/AH=3Fh`. Для `scedata` статически найдены аргументы: handle, буфер, count 8143 (`TASK-007B`).
- Для `HEXMAP`-подобной точки: открытие, seek `AH=42h`, read 196 байт (`TASK-007C`).
- Для `MAPINF`-подобной точки: seek на `(DS:0043 & 127) × 1600`, read 1600 байт (`TASK-008`). Имя файла — `inferred`.
- Helper-функция с таблицей из 8 слов разобрана полностью: 246 инструкций, очередь пуста, нет вызовов вне набора. Побайтовая сверка в `verify_helper_flow.py`. Явного обращения к DS нет.
- `helper_write_footprint.py` проверил 8 nonstack-записей: при целых loop-локалах и отсутствии aliasing `DS:0043` не затрагивается. Это условное утверждение (`TASK-009`).

**Игра в DOSBox.** Ручное прохождение записано (`PLAY-001`). Клавиатурный путь до стратегической карты France через `oe-boot newgame`. Мышь работает через INT 33h.

## 5. Что не подтверждено

- **Значение DS** во всех точках открытия файлов. Пока неизвестно, какой адрес в памяти соответствует открываемому имени.
- **Успешность чтений** и фактическое имя открытого файла.
- **Формат записей** `scedata`: интерпретация блоков по 800 байт не доказана.
- **Геометрия карты** и смысл `mapinf`/`mappno`/`hexdisp`.
- **Таблица батальонов/полков в RAM.** Поиск числа 12811 даёт 39 совпадений, кластер около 0x413DE–0x41549. Это кандидат, а не результат. Нужен дифференциальный метод: изменить параметр, пересканировать.
- **Формулы боя** и адреса игровых таблиц.
- **Генезис-мануал** не получен (ссылка в `source_index.yaml`). Расхождения консоли и DOS записаны в `unverified_questions.md`.

## 6. Внешние модели и бюджет

- **Локальные модели (`LOCAL-001`).** Пять запросов, три ответа с gemma4:e4b. Один ответ неверный (AH=3Fh), два верных. Модель на Mac не идентифицирована; выбор gpt-oss по имени в интерфейсе невозможен. Это адаптивная проба, не измерение точности.
- **Jev (`JEV-001`, `call-005`, `call-006`).** Синтетические наборы: 16/16, затем baseline 5/6 (ошибка — пропущено обнуление AH). Аудиты 6/6. Ключ DPAPI работает, секреты в вывод не попадают.
- **Лимиты.** Cap runner — $0.50 на день. Срок продлён до 2026-10-30T00:00+01:00 (ранее было 08:00 по Будапешту 29 октября). Счётчик не сброшен. После срока без нового разрешения вызовов не делать.
- **Ночная автоматизация `operation-europe`** по STATE.md после 08:00 29 октября приостановлена. Новых автозапусков не обещать.

## 7. Следующие шаги

1. **Breakpoint в DOSBox-X** на `INT 21h/AH=3Dh` в одной из пяти точек. Сохранить DS, DX и короткую строку DS:DX в локальный файл. До этого не повышать связь с SCEDATA выше `inferred`.
2. Восстановить `DOSBOX_API_TOKEN` в переменной окружения. Старый файл `private/dosbox/api_token.txt` не трогать и не читать.
3. Пройти экраны Info (Units, Cities, Commanders, Armaments, Victory) клавиатурой, снять скриншоты (`MAP-001`).
4. Найти таблицу полков и батальонов дифференциально по числам с экрана Info-Units.
5. Закончить анализ helper: диапазоны индексируемых MOV-записей и возможное SS/DS aliasing.

## 8. Правила, которые нельзя забывать

- Оригиналы не менять и не коммитить.
- Гипотезы помечать статусом достоверности.
- Токены и ключи только в переменных окружения, не в файлах и отчётах.
- EXE запускать только в DOSBox/DOSBox-X.
- Графику и EXE не патчить без решения пользователя.
- Для каждой задачи выбирать свободный ID эксперимента заранее: каталог `TASK-008` уже содержит старую пробу от 2026-10-27, и новый `report.json` был записан поверх прежнего.
